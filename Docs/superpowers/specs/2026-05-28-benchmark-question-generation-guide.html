Step 1 — Ingest SEC Data into DuckDB

⚠ Why you can't skip this

The existing axioms/benchmark.py resolves values from 3 local iXBRL files (AAPL, MSFT, TSLA). You can't generate 300 diverse questions from 3 companies. The SEC publishes pre-extracted XBRL — one API call gives you every fact a company ever reported.

1a. The fact table schema

CREATE TABLE facts (
  fact_id       VARCHAR,     -- hash of (cik, concept, period_end, unit, accession, dim_hash)
  cik           INTEGER,
  entity_name   VARCHAR,
  taxonomy      VARCHAR,     -- 'us-gaap' | 'dei' | 'ifrs'
  concept       VARCHAR,     -- the XBRL tag, e.g. 'Revenues'
  period_type   VARCHAR,     -- 'instant' | 'duration'
  period_start  DATE,
  period_end    DATE,
  unit          VARCHAR,     -- 'USD' | 'shares' | 'pure' | 'USD/shares'
  decimals      INTEGER,
  value         DOUBLE,
  accession     VARCHAR,     -- filing accession number (provenance)
  form_type     VARCHAR,     -- '10-K', '10-Q', etc.
  filed_date    DATE,
  fy            INTEGER,     -- fiscal year
  fp            VARCHAR,     -- fiscal period ('FY', 'Q1', etc.)
  frame         VARCHAR      -- SEC frame identifier
);

CREATE INDEX idx_entity_concept ON facts(cik, concept, period_end);
CREATE INDEX idx_cross_entity ON facts(concept, period_end);

1b. The ingestion script

For each S&P 500 company, the script does three things:

#ActionDetails
1 Fetch GET https://data.sec.gov/api/xbrl/companyfacts/CIK{cik:010d}.json
2 Parse JSON nests facts under facts.{taxonomy}.{concept}.units.{unit}[]
3 Insert Each entry has val, accn, fy, fp, form, filed, frame, start, end — map to schema above
◆ Rules for SEC API access
  • User-Agent header required: "FinSearch Lab felixflyingt@gmail.com" (SEC blocks without it)
  • Rate limit: ≤10 req/s — use time.sleep(0.1) between calls
  • Idempotent: INSERT OR IGNORE keyed on fact_id so re-runs don't duplicate
  • Bulk alternative: Download companyfacts.zip once instead of making 500 API calls

The resolver tries tags in order, returns the first match. If none match → the metric is unavailable for that company. Skip, don't guess.

Step 2 — Write Question Templates

A template is a Python class that queries the fact store, checks data sufficiency, generates a natural-language question, computes the gold answer, and returns a structured case.

Base interface

@dataclass
class BenchmarkCase:
    question:        str
    gold_answer:     float
    gold_answer_unit:str    # 'USD', 'ratio', 'percentage_points', 'percent'
    gold_fact_path:  list[str]  # fact_ids used to derive the answer
    required_facts:  dict   # human-readable label → value
    K:               int    # hop count (number of facts needed)
    track:           str    # 'R' (retrieval) or 'C' (computation)
    template_id:     str
    difficulty:      str    # 'easy' | 'medium' | 'hard'
    as_of_date:      str    # ISO date — temporal cutoff
    entity:          dict   # {'cik': ..., 'ticker': ..., 'name': ...}

class Template(ABC):
    template_id: str
    track:       str

    @abstractmethod
    def generate(self, db: duckdb.DuckDBPyConnection) -> list[BenchmarkCase]:
        """Walk the fact store and emit all valid cases."""
        ...

The 7 templates

Ordered from easiest to hardest to build. Start with Templates 1–2 — they validate your pipeline end-to-end before you invest in harder ones.

Template 1: Single-Fact Lookup

Track R K=1 Easy Start here

The baseline. Not interesting by itself, but establishes the pipeline and gives K=1 data points.

◆ Example

"What was Apple's total revenue for FY2023?" → $383,285,000,000

Pattern: "What was {company}'s {metric} for {period}?"

FOR EACH company IN universe: FOR EACH canonical metric: FOR EACH annual period (10-K): IF fact exists → emit case

Limit output: ~30 cases across diverse companies/metrics. Don't emit thousands.

Template 2: Period-over-Period Change

Track R K=2-4 Medium Start here

Measures change between two periods — absolute delta or percentage change.

◆ Example

"By how much did Microsoft's R&D spending change from FY2022 to FY2023?" → +$2,195,000,000

Pattern: "By how much did {company}'s {metric} change from {period1} to {period2}?"

FOR EACH company: FOR EACH canonical metric: Find all periods where the metric exists FOR EACH consecutive pair (or 2-year / 3-year gap): Compute delta and percentage change Emit case with K = 2

Variants: absolute change (K=2), percentage change (K=2), multi-year change (K=3-4).

Template 3: Ratio Derivation

Track C K=2-4 Medium

Agent must compute a ratio from fetched facts. Reuse the math in axioms/engine.py.

◆ Example

"Calculate Tesla's current ratio for FY2023." → 1.73

Pattern: "Calculate {company}'s {ratio} for {period}."

FormulaInputsK
Gross margin(revenue - cogs) / revenue × 1002
Current ratiocurrent_assets / current_liabilities2
Debt-to-equitytotal_liabilities / equity2
ROAnet_income / total_assets × 1002
ROEnet_income / equity × 1002
FOR EACH company: FOR EACH ratio formula: FOR EACH period: Resolve all input metrics via CANONICAL_METRICS IF all inputs found → compute gold answer → emit case

Template 4: Cross-Entity Comparison

Track R K=2-4 Hard

Agent must retrieve the same metric for multiple companies and compare.

◆ Example

"Which of AAPL, MSFT, GOOGL had the highest revenue in FY2023?" → MSFT, $211,915,000,000

Pattern: "Which company had the highest {metric} among {set} in {period}?"

Pick 3–5 companies (e.g. same sector or top-N by size) FOR EACH canonical metric: FOR EACH period: Fetch metric for all companies in the set IF all values exist AND max is unambiguous → emit case

Skip if two companies report the same value — the gold answer must be unambiguous.

Template 5: Conditional Lookup

Track R K=2-3 Hard

Two-hop reasoning: first find a year meeting a condition, then look up a different metric for that year.

◆ Example

"What was Apple's net income in the first year its revenue exceeded $300B?"
Step 1: Find FY2021 (revenue $365.8B > $300B) → Step 2: Net income = $94,680,000,000

Pattern: "What was {company}'s {metric_B} in the first year its {metric_A} exceeded {threshold}?"

FOR EACH company: FOR EACH pair (metric_A, metric_B): Sort metric_A values chronologically Pick threshold between company's min and max for metric_A Find first period where metric_A > threshold IF found AND metric_B exists for that period → emit case

Threshold choice matters: pick a value that makes the "first year exceeding" neither the first nor last year of data.

Template 6: Multi-Step Valuation

Track C K=4-6 Hard

Multi-step deterministic calculation chaining multiple facts and formulas. Limit to metrics derivable purely from filing data (no market cap).

◆ Example

"Compute Microsoft's DuPont decomposition (net margin × asset turnover × equity multiplier) for FY2023 and identify which component changed most vs FY2022."

Start with these chains:

  • 3-year average of a ratio (e.g. avg gross margin FY2021–2023)
  • DuPont decomposition (net margin × asset turnover × equity multiplier)
  • Year-over-year growth rate of a derived metric

Template 7: Multi-Constraint Filter

Track R K=3-5 Hard

Scan companies to find those meeting multiple conditions simultaneously.

◆ Example

"Which S&P 500 companies had current ratio > 2 and debt-to-equity < 0.5 in FY2023?"

Pattern: "List S&P 500 companies with {condition_A} AND {condition_B} in {period}."

FOR EACH period: FOR EACH pair of constraints: Scan all companies, compute both metrics Filter to those meeting both conditions IF result set is 2–15 companies → emit case IF result set is 0 or >15 → skip (impossible or trivial)

Step 3 — Generate the Pilot Benchmark

Main entry point

def generate_benchmark(db_path: str, output_path: str, target: int = 300):
    db = duckdb.connect(db_path, read_only=True)
    all_cases = []

    for template_cls in ALL_TEMPLATES:
        cases = template_cls().generate(db)
        all_cases.extend(cases)

    # Apply validity controls
    cases = deduplicate(all_cases)
    cases = balance_difficulty(cases, target)
    cases = leakage_scan(cases)

    with open(output_path, 'w') as f:
        json.dump([asdict(c) for c in cases], f, indent=2)

    print_stats(cases)

Validity controls

These quality checks are what make this a real benchmark, not just a pile of generated questions:

#ControlWhat it checks
1 De-duplication Two questions testing the same (company, metric, period) with different wording are duplicates. Keep one.
2 Leakage scan Gold answer must NOT appear in the question text. Check: str(gold_answer) not in question.
3 Difficulty balance K (hop count) determines difficulty. Sample to match the target distribution above.
4 Temporal validity Every case has an as_of_date. Only facts with filed_date ≤ as_of_date are visible. Prevents future data leakage.
5 Fact completeness Every fact_id in gold_fact_path must exist in the DuckDB store. Missing = discard.
6 Human spot-check Manually review ~30 random cases. Question makes sense? Gold answer correct? Difficulty reasonable?
Acceptance Gate — Steps 2 + 3
  • ≥300 cases generated
  • K distribution covers K=1 through K≥4
  • Both tracks represented (R and C)
  • No duplicate fact-paths
  • No leaked answers in question text
  • 30-case human spot-check passes
  • Output is valid JSON, every fact_id resolves in the store

Explicitly NOT in Scope

These are important but come later. Don't build them now:

  • Grading harness — how to score an agent's answers against the gold labels
  • PVC services — RetrieveEvidence, TraceClaim, ValidateMetric as MCP tools
  • Agent wiring — routing FinSearch retrieval through the truth layer
  • Cloud deployment — Aurora / Neptune / leaderboard
  • Strategy-coding execution — backtest harness for Track C stretch goals

Quick Reference: SEC API

⚠ Fair access rules

All requests must include a User-Agent header with your name and email. Max ~10 requests/second. Prefer bulk companyfacts.zip for the initial backfill. 

# All facts for a company (primary ingest path)
curl -H "User-Agent: FinSearch Lab felixflyingt@gmail.com" \
  "https://data.sec.gov/api/xbrl/companyfacts/CIK0000320193.json"

# Bulk download — all companies, no rate limits
curl -O "https://www.sec.gov/Archives/edgar/daily-index/xbrl/companyfacts.zip"

# S&P 500 CIK list
curl "https://www.sec.gov/files/company_tickers.json"
